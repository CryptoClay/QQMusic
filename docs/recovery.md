# Резервная копия и восстановление QQMusic

Из корня проекта в PowerShell (нужен запущенный Docker Desktop):

```powershell
.\scripts\Recovery.ps1 -Action Backup -Archive E:\QQMusicBackups\music.qqm
.\scripts\Recovery.ps1 -Action Restore -Archive E:\QQMusicBackups\music.qqm -Destination D:\QQMusic-Restored
.\scripts\Recovery.ps1 -Action Verify -Destination D:\QQMusic-Restored
```

Backup и Restore запрашивают пароль, минимум 16 символов. Сохраните его в менеджере паролей: без него архив не восстановить. Для запуска без диалога можно заранее задать `QQM_BACKUP_PASSPHRASE` в окружении процесса. Архив и каталог восстановления не перезаписываются. Wrapper определяет работающие контейнеры `qqmusic_*` или прежние `homemusic_*` и фактический том Navidrome. Для нестандартной установки есть параметры `-HubContainer`, `-NavidromeContainer`, `-Image`.

В архив входят согласованные снимки SQLite Hub и Navidrome, вся папка `library` с обложками, cookies YouTube (если есть), `.env`, `config.yaml`, `navidrome.toml`. Настройки содержат ключи шифрования и авторизации, поэтому весь архив шифруется AES-256-GCM с ключом Scrypt и случайными salt/nonce. Пароль и расшифрованные секреты не выводятся. Сначала проверяется подлинность всего архива, затем допустимость путей и SHA-256 каждого файла, целостность обеих баз и расшифровка сохранённых паролей/ссылок.

Обычный Backup не останавливает сервисы: SQLite backup API включает подтверждённые WAL-транзакции. На время захвата приостановите загрузки, импорт, редактирование и удаление музыки в интерфейсе: SQLite и файловая система не имеют общей транзакции. Изменение файла во время его копирования прерывает операцию. Архив создаётся через временные файлы; требуется свободное место примерно на два объёма библиотеки плюс сам архив. Восстановление требует места на расшифрованный архив и две копии файлов во время проверки. Доступ к временной папке и восстановленной `.env` должен быть только у владельца компьютера.

Не включены временные загрузки, корзина, модели embedder, сетевые туннели и их SSH-ключи. Это копия музыкальной библиотеки и данных приложений. Для аварии компьютера храните зашифрованный архив на другом диске/устройстве. Планировщик этим инструментом не создаётся.

## Запуск восстановленной установки

Результат Restore: `hub/hub.sqlite3`, `navidrome/navidrome.db`, `music/library`, `settings/.env`, `settings/config.yaml`, `settings/navidrome.toml`, `manifest.json`. Для отдельной установки подключите эти каталоги к новым Hub и Navidrome, задайте внутренний `NAVIDROME_URL`, `MUSIC_ROOT`, `DATA_DIR`, `CONFIG_FILE` и сохраните ключи из восстановленной `.env`. Используйте отдельные имена контейнеров и сеть. Сначала проверяйте с `DISABLE_BACKGROUND=true`, чтобы сохранённые задания не запускались. Не заменяйте рабочие тома до проверки входа, библиотеки и воспроизведения.

## Выполненная проверка, 12 ноября 2026

Снимок рабочих данных был снят через read-only mounts без перезапуска сервисов. Зашифрованный архив восстановлен, SHA-256 совпали для всех 138 файлов (132 файла библиотеки, включая обложки), SQLite integrity_check прошёл для Hub и Navidrome, сохранённый секрет аккаунта расшифрован. На живых данных было одно такое поле; отдельный автоматический тест проверяет также пароль Nextcloud и зашифрованные ссылки личного плейлиста.

Из копии запущены отдельные Hub и Navidrome в Docker-сети `--internal`, без публикации портов, с отключёнными фоновыми заданиями. Проверены health обоих сервисов, вход существующим аккаунтом, API библиотеки с 67 треками и чтение 1024 байт аудио с HTTP 206. Миграция личных плейлистов применена к копии. После проверки тестовые контейнеры и сеть удалены, расшифрованная тестовая копия перемещена в корзину Windows; в проекте оставлен только отчёт без секретов (`.agent-work/recovery-drill/report.json`).

Автоматические тесты дополнительно проверяют неверный пароль, повреждённый шифротекст, подмену файла, запрет перезаписи каталога и path traversal в архиве.

## Регулярные копии на будущем сервере

Расписание подготовлено, но не включено. scripts/backup_job.py по умолчанию печатает план; --run разрешает реальное обслуживание. Скрипт использует тот же шифрованный формат, секрет читает из отдельного файла и не печатает его. Архивы хранятся вне проекта и музыки. Удержание затрагивает только архивы, записанные в собственный индекс задания, с совпадающей SHA-256; изменённый или посторонний файл не удаляется. Одновременный второй запуск блокируется.

Для согласованной копии задание останавливает Hub и Navidrome на время захвата и шифрования архива, затем запускает только те контейнеры, которые работали до него. При ошибке также выполняется восстановление прежнего состояния. В этот промежуток сайт недоступен; окно зависит от размера библиотеки. Планировать на время низкой активности. Это не попытка синхронизировать SQLite и меняющиеся файлы без остановки записи.

На Linux скопировать deploy/backup.example.json в /etc/qqmusic/backup.json, исправить пути и выбрать каталог на другом диске или сетевом хранилище. Создать /etc/qqmusic/backup.key с паролем минимум 16 символов и правами 600. Не передавать пароль аргументом командной строки и не добавлять его в Git. Проверить план:

```bash
python3 scripts/backup_job.py --config /etc/qqmusic/backup.json
```

В согласованное время выполнить один ручной запуск с --run, восстановить его в отдельную установку и проверить вход/аудио. Только затем установить deploy/qqmusic-backup.service и deploy/qqmusic-backup.timer в /etc/systemd/system и включить таймер. В шаблоне пути /opt/qqmusic и время 04:30 по часовому поясу сервера; изменить под свою установку. Persistent=true может запустить пропущенную копию после включения сервера — учитывать окно обслуживания. Проверять systemctl status и journalctl задания; сам факт наличия таймера не подтверждает успешную копию.

Для Windows есть scripts/Install-BackupTask.ps1 -Config <путь>: без -Apply это только проверка плана. -Apply регистрирует ежедневную задачу под текущим пользователем; без отдельной настройки принципала она рассчитана на его активный сеанс. Защитить файл пароля правами ACL пользователя. На сервере предпочтителен вариант systemd с контролируемым окном обслуживания.

Пароль должен храниться отдельно от архивов. Периодически повторять восстановление на отдельном месте, а не ограничиваться списком файлов. Скрипт не настраивает удалённое хранилище и не включает расписание автоматически.
