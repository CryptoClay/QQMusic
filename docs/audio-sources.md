# Internet Archive и личная музыка Nextcloud

## Internet Archive

Источник зарегистрирован как `internet_archive`. Он доступен в поиске → «Файлы» и используется
как резерв для полной записи при прослушивании и скачивании. Основные источники сохраняют приоритет:

```yaml
sources:
  download_fallback: [soundcloud, internet_archive]
```

Для отключения уберите `internet_archive` из `download_fallback`. В поиске файлов источник останется доступен.
Для проверки конкретного источника после входа: `GET /api/search/providers?q=Artist%20-%20Song&provider=internet_archive`.
Найденные файлы проходят обычное сопоставление исполнителя, названия, версии и длительности;
проверка скачанного аудио также сохраняется. Каталог содержит концерты и редкие записи, поэтому
совпадение с коммерческим релизом не гарантируется.

Адаптер использует Advanced Search и Metadata API, исключает закрытые коллекции, запрет скачивания,
приватные файлы, явно помеченные семплы и неподдерживаемые форматы. Общий бюджет поиска — 5 секунд:
при его исчерпании возвращаются уже найденные файлы. Поддерживаются MP3, FLAC, Ogg, Opus и M4A,
прослушивание с Range и скачивание с прогрессом. Ключ API не нужен.

Метаданные не доказывают полноту записи или наличие прав на её повторное использование.
Документация API: https://archive.org/developers/metadata-schema/index.html

## Nextcloud: личное подключение

Откройте **Настройки → Nextcloud** (на ПК также есть пункт в боковом меню).
Администратор первым указывает HTTPS-адрес сервера, имя пользователя, пароль приложения и музыкальную
папку и нажимает «Сохранить и проверить». Обычные пользователи могут подключить свои аккаунты к
добавленным администратором серверам. Дополнительный разрешённый сервер оператор может указать
переменной NEXTCLOUD_URL в локальном .env. Администратор задаёт доверенный сетевой адрес: допускается
и собственный сервер в домашней сети; обычные пользователи не могут вводить произвольные внутренние адреса.

Адрес — корень сервера, например https://cloud.example.com или https://cloud.example.com/nextcloud,
без /remote.php/dav. Имя пользователя — внутренний ID Nextcloud. Пароль приложения создаётся
в личных настройках безопасности Nextcloud. Путь, например Music или Музыка/Рок, задаётся относительно
файлов пользователя; пустое значение означает их корень. После сохранения пароль не возвращается
браузеру: пустое поле сохраняет прежний пароль при неизменных сервере и имени пользователя.

В разделе «Музыка в облаке» можно искать по имени файла, слушать и скачивать найденные записи.
Предпочтительное имя — «Исполнитель - Трек.ext». Воспроизведение идёт в плеере на странице Nextcloud;
при переходе с неё останавливается. Поддержка конкретного кодека зависит от браузера, транскодирования
облачных файлов нет. Облако не меняется: используются только PROPFIND и GET.

Пароли хранятся зашифрованными ключом HUB_SECRET_KEY в таблице nextcloud_connections.
Файлы проксируются через отдельный API, без общих кешей и без копирования в общую библиотеку Navidrome.
Каждая зашифрованная ссылка требует активной сессии владельца, действует 12 часов и отзывается
при изменении или удалении подключения. Ответы имеют Cache-Control: private, no-store.
Отключение удаляет сохранённые данные подключения, не затрагивая файлы в Nextcloud.

Поиск ограничен 5 секундами, глубиной 4 и 2000 записями. При превышении времени сузьте папку поиска.
Отдельный файл ограничен 500 MiB; доступ за пределы выбранной папки, чужой хост и редиректы запрещены.
Поддерживаются MP3, M4A, AAC, FLAC, Ogg, Opus и WAV; аудиопоток поддерживает Range для перемотки.

API (только текущий пользователь):

- GET /api/nextcloud/connection — настройки без пароля и список разрешённых серверов.
- PUT /api/nextcloud/connection — сохранить подключение, отозвать старые ссылки.
- DELETE /api/nextcloud/connection — отключить и удалить данные подключения.
- POST /api/nextcloud/test — проверить чтение папки.
- GET /api/nextcloud/files?q=... — поиск личных файлов.
- GET /api/nextcloud/audio?file=... — поток; download=1 — скачать на устройство.

Отдельный диагностический адаптер по-прежнему можно запускать через python -m app.providers.nextcloud.
Он читает NEXTCLOUD_URL, NEXTCLOUD_USER, NEXTCLOUD_PASSWORD и NEXTCLOUD_FOLDER из окружения.
Эти переменные не привязывают личный аккаунт к веб-интерфейсу: для этого используются настройки выше.
Никогда не присылайте файл .env или пароль в чат.

Применение обновления (миграция создаёт новую таблицу при старте Hub): docker compose up -d --build hub.
Перед обновлением сохраните обычную резервную копию данных Hub и ключа HUB_SECRET_KEY.
Работа с реальным Nextcloud проверяется владельцем после ввода его адреса и учётных данных.

Документация WebDAV: https://docs.nextcloud.com/server/latest/developer_manual/client_apis/WebDAV/basic.html
