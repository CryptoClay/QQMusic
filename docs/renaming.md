# Переход HomeMusic → QQMusic

Серверные пакеты, веб, Docker-проект, контейнеры, образы, CSS, события браузера и новые аудиотеги используют `qqmusic`. Android и его release-скрипт отложены. Рабочую папку репозитория можно переименовать отдельно после остановки инструментов, которые её используют; относительные пути Compose от имени папки не зависят.

## Совместимость данных

- Базы, пользователи, ключи шифрования, библиотека и её UUID не меняются.
- Новый cookie `qqmusic_session` заменяет действующий `hm_session` при обращении к API; выход отзывает обе сессии.
- Настройки браузера, очередь, позиция, идентификатор устройства и неотправленные события читаются по прежним ключам `hm-*`, если новых ещё нет. Запись использует `qqmusic-*`; удаление очищает оба имени. Это работает на том же origin (протокол, домен, порт). При смене домена браузер данные автоматически не переносит.
- PWA использует новые кэши и удаляет только собственные устаревшие кэши. Незавершённый Web Share из прежней IndexedDB переносится с сохранением вложенных файлов.
- Новые файлы получают `QQMUSIC_*`, старые `HOMEMUSIC_*` продолжают читаться. Navidrome сопоставляет оба набора с прежними **внутренними PID-полями**: их переименование изменило бы идентичность библиотеки. UUID не генерируются заново; массовой перезаписи музыки нет.
- Прежние HTTP-заголовки воспроизведения и Android-мост поддерживаются наряду с новыми. `hm:<id>` — источник Hitmoz, его ссылки переименовывать нельзя.

## Переключение существующего сервера

Сначала сделать [резервную копию](recovery.md). Не запускать старый и новый стек одновременно на одних базах.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Migrate-QQMusic.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Migrate-QQMusic.ps1 -Apply
```

Без `-Apply` скрипт только проверяет Docker. С `-Apply` он определяет настоящие тома Hub/Navidrome и при наличии embedder; записывает `QQMUSIC_*_VOLUME` в `.env`. Копия прежнего `.env` остаётся в игнорируемой `.agent-work/`. Профили работающих embedder/туннеля сохраняются; прежний SSH-пользователь VPS подставляется, если другой не задан.

Образы собираются **до** остановки старых сервисов: ошибка сборки не прерывает работу старого сервера. Затем скрипт останавливает прежние контейнеры, запускает `qqmusic` и ждёт готовности. Старые контейнеры и тома не удаляются.

Физические тома прежней установки могут остаться `homemusic_*`: это совместимость данных. Новая установка создаёт `qqmusic_*`. Не удалять привязки из `.env`: иначе Compose создаст пустые базы. `MUSIC_ROOT`, `HUB_SECRET_KEY`, `ND_PASSWORDENCRYPTIONKEY` сохраняются прежними.

Проверить `docker compose ps`, вход, плейлисты, лайки, воспроизведение и загрузку. `Recovery.ps1` определяет работающий новый/старый контейнер и реальный том Navidrome; при нестандартных именах есть `-HubContainer`, `-NavidromeContainer`, `-Image`.

## Откат

```powershell
docker compose stop
# Запускать только ранее работавшие сервисы; пример основного набора:
docker start homemusic_navidrome homemusic_youtube_pot homemusic_hub
```

Перед запуском прежнего стека убедиться через `docker ps`, что новые Hub и Navidrome остановлены. При необходимости вернуть `.env` из `.agent-work/` и прежний коммит исходников. Тома удалять не нужно.

## VPS

Действующий VPS не нужно менять для переименования локального сервера: оставить `VPS_USER=homemusic-tunnel`. Новая установка `gateway/vps/setup-vps.sh` создаёт `qqmusic-tunnel`, юниты `qqmusic-*` и новый блок Caddy. При повторном запуске заменяет прежний управляемый блок, включает новый firewall до отключения старого и оставляет прежнего SSH-пользователя для отката. После успешной настройки VPS переключить `VPS_USER=qqmusic-tunnel` и пересоздать локальный туннель. Удалённо скрипт автоматически не запускается.
