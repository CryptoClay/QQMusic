# Публичный сервер QQMusic

Целевой вариант: Linux с Docker Engine и Docker Compose 2.24.4 или новее, домен с DNS на этот сервер. Сначала проверить установку на отдельном сервере; рабочую Windows-установку командами ниже не менять.

## Подготовка

Если HTTPS уже обслуживает Nginx Proxy Manager на другом сервере, использовать [вариант с внешним прокси](reverse-proxy.md) вместо конфигурации Caddy ниже.

1. Скопировать .env.example в .env и config.example.yaml в config.yaml. Сгенерировать HUB_SECRET_KEY и ND_PASSWORDENCRYPTIONKEY по README. Ключи не менять после начала использования.
2. Задать MUSIC_ROOT абсолютным путём, например /srv/qqmusic/music, создать в нём library. Ограничить доступ к .env, config.yaml, резервным копиям и SSH-ключам.
3. Задать QQM_DOMAIN=music.example.com в .env, заменив имя своим доменом. Не включать SMTP-регистрацию до проверки приглашений, квот и лимитов пользователей.
4. Открыть на маршрутизаторе/сервере только нужные для сайта 80/tcp, 443/tcp и при использовании HTTP/3 443/udp. SSH защищается отдельно. Порты 8081, 4533 и сервис рекомендаций наружу не публиковать.

```bash
docker compose -f docker-compose.yml -f deploy/compose.public.yml config --quiet
docker compose -f docker-compose.yml -f deploy/compose.public.yml up -d --build
docker compose -f docker-compose.yml -f deploy/compose.public.yml ps
```

Override оставляет Hub и Navidrome на 127.0.0.1; Caddy — единственная внешняя точка входа. Он получает и продлевает сертификат для домена, перенаправляет HTTP на HTTPS и проксирует SSE без задержки буфера. Данные сертификатов сохраняются в отдельных томах. Не открывать напрямую порт Uvicorn: доверие к proxy-заголовкам рассчитано на этот закрытый upstream.

Для первого создания администратора Navidrome использовать SSH-туннель с собственного компьютера:

```bash
ssh -L 4533:127.0.0.1:4533 user@server
```

Открыть http://127.0.0.1:4533 на своём компьютере, создать администратора с данными из .env и затем войти в https://music.example.com. В публичном режиме PUBLIC_MUSIC_URL пуст: отдельный веб-интерфейс Navidrome не публикуется. Подключение нативных клиентов — отдельная настройка.

## Защита и ограничения

Публичный режим требует корректный HTTPS PUBLIC_HUB_URL и ключ Fernet. Проверяются Host и Origin записывающих браузерных запросов; cookie получает Secure/HttpOnly/SameSite=Lax. Попытки входа ограничены на IP и минуту; таблица ограничителя имеет фиксированный максимальный размер. Исключение для локального /healthz не открывает API через произвольный Host. Ограничитель хранится в памяти и рассчитан на один процесс Hub, как штатный Dockerfile; перед несколькими репликами нужны общий ограничитель, согласование очередей и другая схема БД.

Это защита базового развёртывания, не защита от объёмной сетевой атаки. Перед приглашением пользователей задать им бюджеты очереди/места/загрузки, проверить место на диске и доступность резервных копий. Учётная запись администратора должна иметь отдельный сильный пароль. Работа внешних источников зависит от их ограничений; ошибки и cooldown должны оставаться видимыми.

Для HTTP в домашней сети PUBLIC_MODE оставить false. Браузерные функции, которым нужен защищённый контекст, по IP/HTTP ограничены; публичный вариант использует HTTPS.

## Приёмка после развёртывания

- Домен открывается без предупреждений сертификата, HTTP перенаправляет на HTTPS.
- Через внешний адрес доступны сайт и аудио; Hub/Navidrome недоступны напрямую на 8081/4533.
- Вход, выход, приглашения, диапазон аудио, загрузка файла и SSE работают с компьютера и телефона.
- Обычный аккаунт не видит чужие личные данные и административные страницы.
- В шторке телефона проверены пауза и переключение треков; внешний вид кнопок зависит от ОС/браузера.
- Создана и проверена внешняя зашифрованная резервная копия, доступен порядок отката.

Публичный домен и правила будущего сервера невозможно проверить на локальном ПК заранее. Выполнить этот список перед открытием регистрации и приглашением внешних пользователей.

Источники по прокси: [автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https), [reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).
