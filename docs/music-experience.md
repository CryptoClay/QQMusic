# Музыкальные возможности для нескольких пользователей

Новые данные хранятся в SQLite Hub: `music_editorial`, `music_private`, `music_preferences`. Миграция `d9a2f5b81c03` добавляет таблицы; существующие треки, аккаунты и файлы не переписывает. Полная резервная копия Hub включает эти данные и загруженные обложки.

## Где искать

- «Ещё → Музыка и звук»: предпочтение оригиналов, режим радио, эквалайзер, выравнивание громкости, crossfade.
- Меню любого трека → «Текст, версия и заметки». В большом веб-плеере этот блок доступен во вкладке «Текст песни».
- «Ещё → Мои заметки и метки»: поиск по своим записям, точная метка, воспроизведение подборки в веб-плеере. Выдаются до 200 подходящих записей.
- «Ещё → Мои музыкальные итоги»: выбор месяца, фактическое время прослушивания, любимые исполнители, треки и открытия. «Давно не включали» — ранее прослушанные несколько раз песни, которые не слушались минимум 30 дней, по всей собственной истории.
- Страница исполнителя или альбома из каталога либо Navidrome: общая карточка с описанием, участниками, связанными проектами и собственной обложкой. Существующая дискография сохранена. Карточки заполняются администратором; биографии не генерируются и не подставляются автоматически.

## Общее и личное

Общие тексты, сведения об исполнителях/альбомах и подтверждения версий доступны всем вошедшим пользователям. Изменять их может только администратор. Описания и тексты выводятся как обычный текст, без исполнения HTML. Внешние изображения по произвольным URL не загружаются: обложка принимается отдельным upload, проверяется и пересохраняется в JPEG до 512 px без исходных метаданных.

Заметки, метки, личные тексты, предпочтения и итоги изолированы по `current_user.id`. Новые API не принимают `user_id`, позволяющий выбирать другого владельца. Ответы с личными данными имеют `Cache-Control: private, no-store`. Клиентский кеш настроек привязан к аккаунту и сбрасывает активные настройки при смене пользователя. Администратор также видит только собственные заметки через эти API.

## Тексты

Поддерживаются обычный текст и LRC: `[01:23.45]Строка`. При воспроизведении активная строка подсвечивается, прокручивается внутри блока текста; нажатие перематывает основной веб-плеер. Личный текст имеет приоритет над общим. Пустые поля личного текста возвращают общий вариант.

«Найти текст в LRCLIB» отправляет название, исполнителя и длительность в [официальный API LRCLIB](https://lrclib.net/docs). Это явное действие пользователя. Результат сначала открывается в редакторе: можно сохранить только себе либо администратору опубликовать для всех. Ссылка на источник сохраняется. При отсутствии текста или недоступности сервиса остаётся ручной ввод. Размер ответа ограничен 256 KB, ожидание — 8 секунд; перенаправления не выполняются. Тексты не скачиваются массово и не отправляются на публикацию в LRCLIB.

## Подтверждённые версии

`unknown` означает отсутствие подтверждения; `original` и `edited` назначаются администратором вручную для конкретного provider-файла или песни Navidrome. Каталожную запись без выбранного файла подтвердить нельзя. Explicit, название «без цензуры», дата загрузки и наличие нецензурных слов сами по себе не считаются подтверждением.

В поиске файлов есть отметки и фильтры по версии. Для изменённого файла администратор может указать идентификатор конкретного оригинала из другой карточки. При предпочтении оригиналов Hub направляет воспроизведение на указанную версию; если замена не указана, возвращает понятную ошибку. Циклы замен ограничены. Настройка не переписывает общую кешированную запись выбора источника другого пользователя. При скачивании подтверждённые оригиналы идут перед неизвестными, подтверждённые изменённые версии пропускаются. Неизвестные записи остаются доступными: это предпочтение оригиналов, а не гарантия проверки всей коллекции.

Навидром-клиенты, обращающиеся напрямую к Navidrome, не проходят через выбор версий Hub. Сведения о версии импортированного файла по возможности связываются с исходным download item.

## Радио и итоги

Радио использует существующие генераторы похожих треков и звуковые векторы embedder, когда сервис доступен. В плеере можно выбрать больше знакомого, баланс или больше открытий; настройки аккаунта задают вариант для новых запусков радио из меню. Это желаемые доли, а не гарантия точного состава каждого блока. При недоступном embedder продолжают работать остальные источники рекомендаций.

Итоги используют существующий расчёт попыток прослушивания, а не сумму всех `progress`-событий. Повторные контрольные точки не удваивают минуты. Старые события без измеренного времени могут давать прослушивания при нулевом измеренном времени. Часовой пояс берётся из браузера, данные других пользователей не включаются.

## Звук

Эффекты применяются к основному веб-плееру QQMusic. Отдельный плеер Nextcloud и нативный Android/Navidrome-плеер используют свои звуковые настройки.

Эквалайзер: шесть полос 60, 170, 350, 1000, 3500 и 10000 Hz, от −12 до +12 dB; есть пресеты. Положительные усиления компенсируются запасом по уровню. Выравнивание — ограниченная плавная регулировка по RMS текущего звука и ограничитель пиков, а не предварительный анализ всей библиотеки по ReplayGain/EBU R128.

Crossfade от 0 до 10 секунд работает между следующими записями очереди при работающем Web Audio. Для коротких треков окно ограничено 10% длительности; для повторения одного трека переход не запускается. Предыдущий элемент продолжает играть до готовности нового, затем уровни меняются плавно. Его события не меняют состояние уже нового трека. Пауза, перемотка, ручной переход, ошибка, остановка и смена аккаунта освобождают предыдущий элемент. При долгой буферизации переход может сократиться; браузеры без Web Audio сохраняют обычное последовательное воспроизведение.

## Проверки

API-тесты проверяют изоляцию двух пользователей, запрет публикации общих данных обычным пользователем, личный приоритет текстов, фильтры заметок, связь с библиотечной записью, подтверждения конкретных файлов, сохранение предпочтений, выбор/скачивание оригиналов, безопасные обложки, ошибки LRCLIB и точность личных итогов.

```powershell
cd web
node --experimental-strip-types --test scripts/test-lrc.mjs scripts/test-audio-effects.mjs
npm run build
```

Для Node-тестов нужен Node с поддержкой TypeScript stripping (локально проверены на Node 24). Проверяются временные метки, повторные LRC-метки, некорректные секунды, соединения аудиографа, усиления, запас громкости, работа AGC, отключение эффектов и расписание плавного изменения уровня.


## Браузерный плеер

На компьютере нижняя панель разделена на трек/лайк, центральное управление с перемоткой и быстрые действия. Перемешивание и повтор доступны прямо в панели. Кнопка громкости выключает звук и возвращает последний ненулевой уровень в текущем сеансе. На узких компьютерах ползунок громкости скрыт, кнопка mute остаётся; полная регулировка есть в большом плеере.

Кнопки текста и очереди открывают панели поверх текущей страницы. Воспроизведение и позиция сохраняются. Большой плеер открывается по обложке, названию или кнопке раскрытия: обложка задаёт фон, очередь и текст разделены вкладками, радио по треку свёрнуто в отдельный блок. Доступ к звуковым настройкам, загрузке и рекомендациям сохранён.

На телефоне остаются обложка, название/источник, лайк, запуск и меню; на экранах от 360 px есть отдельная кнопка следующего трека. На более узком экране используется свайп по названию или управление в большом плеере. Закрытие плеера перенесено в меню «Ещё» → «Закрыть плеер».

Ползунок поддерживает мышь, касание и клавиатуру; отменённый жест и смена трека во время перемотки не перематывают новую песню. Активные режимы подписаны для скринридера, фокус виден с клавиатуры. Индикатор играющего трека в очереди учитывает системную настройку уменьшения движения. Новый внешний вид не меняет механизм получения аудио, учёт прослушивания и настройки сервера.
