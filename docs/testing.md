# Проверки серверной и браузерной версии

Все сценарии используют отдельные каталоги, собственные аккаунты и синтезированные MP3. Рабочие тома и музыка к ним не подключаются. Внешний каталог заменён тестовым ответом, остальные внешние запросы получают 503. Это проверяет приложение и обработку отказа источников, но не скорость или доступность YouTube и других провайдеров.

## Быстрые проверки

```powershell
npm --prefix web ci
npm --prefix web run build
npm --prefix web run test:unit
cd hub
uv sync --frozen --group dev
uv run pytest -q -n 4
```

Сборка проверяет типы приложения, конфигурации и браузерных тестов. npm ci обязателен: сборка не подменяет несовпавший lock-файл обычной установкой.

## Браузерная приёмка

После сборки веба запустить в первом терминале из hub:

```powershell
uv run python ../tests/browser_server.py --port 18082
```

Сервер держит неизменяемую копию сборки и создаёт данные в системном временном каталоге. Он не читает рабочую .env. Публиковать этот стенд в Интернет нельзя: у тестовых аккаунтов известный пароль. Для разработки UI второй терминал может запускать npm --prefix web run dev:fixture; старый UI-мок удалён.

Во втором терминале:

```powershell
cd web
npx playwright install chromium firefox webkit
npm run test:e2e -- acceptance.spec.ts
```

Три проекта: Chromium, Firefox и WebKit с размером экрана телефона. Проверяются вход без randomUUID, переходы и геометрия, появление результатов, плейлист из 90 строк, настоящий аудиопоток, перемотка и скип, таймер сна, отключение сети, изоляция аккаунтов, дистанционная команда и выход.

QQM_E2E_URL задаёт адрес отдельного тестового сервера. QQM_BROWSER_CHANNEL=chrome или msedge позволяет использовать установленный браузер для проекта chromium. Отчёты лежат в web/test-results и web/playwright-report, ошибки сохраняют screenshot/trace/video; они не попадают в Git.

## Длительный прогон

```powershell
$env:QQM_SOAK_SECONDS='7200'
npm run test:soak
```

Это два часа реального времени, не ускоренный таймер. Каждые 2 секунды проверяются ошибка и продвижение настоящего аудио, периодически меняются страницы, отключается и возвращается сеть, выполняется скип. Потеря прогресса более 25 секунд завершает тест ошибкой. JSON-отчёт содержит elapsed_seconds, samples, track_changes, completed и failures. completed=false означает незавершённую проверку. Видео/trace для этого длинного сценария отключены; они остаются у короткой приёмки.

Локальный прогон всех 27 сценариев прошёл в официальном Linux-образе Playwright 1.65.0. В Windows-порте WebKit три сценария воспроизведения не прошли из-за ошибки декодирования тестового аудио; Chromium и Firefox прошли. Поэтому полная матрица выполняется в Linux, а работу Safari проверяют на настоящем устройстве.

Автоматический WebKit не заменяет проверку настоящего телефона: на нём отдельно проверяют фон, экран блокировки, разрешения уведомлений и ограничения энергосбережения ОС.

## GitHub

Workflow Release checks запускается на push в main и pull request. Он проверяет сервер, веб, три браузера, сборку Docker и многопользовательскую нагрузку. Через Run workflow с soak=true дополнительно включается двухчасовой прогон. Отчёты прикладываются к запуску; неудачные проверки запрещают считать сборку готовой к выпуску.

Прогоны нагрузки: [очередь и метаданные](queue-and-metadata.md). Восстановление: [резервные копии](recovery.md). Выпуск: [релизы](releases.md).
