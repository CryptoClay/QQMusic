# Выпуск и откат

Версия кандидата записана в VERSION. Текущий цикл — 0.1.0-rc.1. Кандидат позволяет проверить готовый набор изменений; стабильный тег не ставится автоматически только потому, что прошла сборка.

## Условия выпуска

1. Зелёный workflow Release checks для нужного коммита: сервер, веб, браузеры, Docker и многопользовательский сценарий.
2. Завершённый двухчасовой прогон: completed=true, failures=[], elapsed_seconds не меньше 7200.
3. Проверено восстановление актуальной копии: целостность баз, вход, список библиотеки и диапазон аудио.
4. Проверка на настоящем телефоне: фон, экран блокировки, возвращение сети. Кнопки переключают треки; лайк в системной карточке браузер не предоставляет, внутри QQMusic он доступен.
5. Кандидатом пользуются несколько дней без потери данных, чёрных экранов и необъяснимых остановок плеера. Обнаруженные ошибки исправляются и проверяются снова.

Отчёты тестов показывают фактически проверенное, не подтверждают автоматически ещё не выполненные пункты. Кандидат отмечается prerelease. После приёмки версия меняется на 0.1.0, ставится стабильный тег и публикуются изменения. Android в этот выпуск не входит.

## Установка и обновление

Сначала сохранить зашифрованную копию вместе с ключами, версию Git и идентификатор прежнего образа. На публичном сервере использовать тот же набор compose-файлов, с которым он был развёрнут:

```bash
git fetch --tags
git checkout v0.1.0-rc.1
docker compose -f docker-compose.yml -f deploy/compose.public.yml up -d --build hub
```

На локальной установке достаточно обычного docker compose up -d --build hub. Томам не выполнять down -v. После запуска проверить healthz, вход, библиотеку, аудио, очередь и события. При обновлении браузер должен получить новую сборку; при необходимости перезагрузить страницу.

## Откат

Прежний образ и база образуют пару: старый код может не понимать новую миграцию. Остановить запись, восстановить резервную копию в отдельный каталог и проверить её. Подключить восстановленные каталоги к прежнему образу, выполнить вход и чтение аудио, затем переключить внешний прокси. Не откатывать рабочую SQLite простым git checkout и не заменять её во время работы контейнера. Музыку, добавленную после копии, перед откатом сохранить отдельно.

Инструменты и пример восстановления: [резервные копии](recovery.md). После публичного развёртывания: [приёмка сервера](public-server.md).

Кандидат можно оформить workflow Draft release candidate: передать идентификатор успешного Release checks на том же коммите, запущенного с soak=true. Workflow проверяет SHA, результат, фактическую длительность и продвижение аудио, собирает архив только закоммиченных файлов, SHA256SUMS и создаёт черновик prerelease. Он не публикует стабильный релиз автоматически. Локальный эквивалент упаковки — python scripts/package_release.py --soak-report <путь к завершённому отчёту>.
